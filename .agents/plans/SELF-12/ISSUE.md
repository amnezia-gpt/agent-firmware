# SELF-12: One constant command to update an installed machine

## Metadata

- Type: Feature / installation
- Status: Validating (implemented and tested locally; not yet run on a real host)
- Size / risk: Small / medium (runs the release installer as root)
- Related: [SELF-10](../SELF-10/ISSUE.md), [SELF-11](../SELF-11/ISSUE.md)
- Authorization: owner accepted the proposal and asked to implement and release it (2026-11-14).

## Problem And Outcome

The enrollment command is generated by the authorization server because it carries a one-time code and the
owner's consent. An update carries no secret, and the only varying input, the issuer, is already known to the
installed firmware. The owner should not have to visit any page to get an update command.

## Delivered

- `sudo agent-firmware update`: no arguments and no code. It reads the issuer of this installation from the
  accepted configuration, downloads the installation script of the latest release from its permanent address
  (HTTPS only, redirects to HTTPS only, at most 1 MiB, must be a shell script), and runs it with that issuer.
  Firmware and the workload release pinned by that firmware release are updated together; identity, sign-in and
  data are kept as by any reinstallation.
- The last progress line of an installation names the command.
- Trust is the same as for installation: TLS and release permission on this repository.

## Acceptance Criteria

- [x] The command needs no argument, issuer or code and refuses any argument.
- [x] A failed or malformed download changes nothing and reports `update_download_failed`.
- [x] The installer's own result and error pass through once.
- [ ] `sudo agent-firmware update` updates a real installed host. Not run.

## Not In Scope

Telling the owner that a newer release exists (needs the device to report its firmware version to the control
plane) and unattended automatic updates (belongs with control-plane desired state).
